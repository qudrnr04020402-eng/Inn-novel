# 은빛 여우관 (Silver Fox Inn) — 30일간의 연애 시뮬레이션

변두리 마을 여관 "은빛 여우관"의 젊은 주인이 되어, 30일(4주 + 종장) 동안 네 명의 히로인과 시간을 보내며 마을 뒷산 동굴의 봉인이 깨지는 사건을 헤쳐 나가는 모바일(세로 화면) 우선 비주얼 노벨입니다.
순수 HTML/CSS/JS 로 만들어져 빌드 도구, 프레임워크, 외부 CDN 이 전혀 없습니다. 정적 파일 그대로 GitHub Pages 에 올리면 동작합니다. (전연령, 노출/성적 묘사 없음)

### 30일 구성: 4주 + 종장

달력은 `story/calendar.js` 하나로 정해집니다. **1일차 = 월요일**, **일요일은 휴일**(영업/숙박 없음)입니다. 메인 줄거리는 주마다 2~3일만 대본이 있고, 나머지 날은 "일상일"(데이터로 굴러가는 날)입니다.

| 주(챕터) | 메인 고정일 | 일상일 / 휴일 |
|---|---|---|
| 1주 「새 주인」 (1~7) | **1일** 도착(손님 셋 + 소꿉친구) / **6일(토)** 첫 지진 | 2~5일 일상, 7일(일) 휴일 |
| 2주 「달맞이」 (8~14) | **10일** 저장고 습격(봉인 균열) / **13일** 달맞이 장터(소원 등불, 대규모 지진) | 8·9·11·12일 일상, 14일(일) 휴일 |
| 3주 「왕도의 손님」 (15~21) | **18일** 술렁이는 마을 / **19일** 왕도 사절단 | 15~17·20일 일상, 21일(일) 휴일 |
| 4주 「폭풍 전야」 (22~28) | **24일** 불길한 징조(봉인까지 닷새) / **28일(일)** 폭풍의 밤 | 22·23·25·26·27일 일상 (일요일 28일은 폭풍이 덮어씀) |
| 종장 「봉인」 (29~30) | **29일** 동굴 결전(봉인이 풀리는 날 해 질 녘) | 30일 새벽 카드 -> 엔딩 판정 |

- 주가 시작될 때(8·15·22·29일) **챕터 타이틀 카드**가 나오고, 그 직전 상태가 **"주차 시작 저장"** 칸에 자동 저장됩니다 (불러오기 화면의 둘째 칸).

- 일요일 밤과 폭풍의 밤(28일) 끝에는 **주간 정산 카드**(그 주의 영업/평판/등급/호감도 변화)가 나옵니다. 토요일에는 주차별 마을 행사(장날 / 사냥 대회 / 수확제 준비)가 낮 행동으로 한 번씩 열립니다.
- 봉인이 풀리는 날까지의 시간 표현은 10일차 "열아흐레", 13일차 "보름 남짓", 24일차 "닷새" 로 맞춰져 있습니다. 날짜를 바꾸면 이 대사들도 같이 고쳐야 합니다 (`grep 닷새\|열아흐레\|보름 story/`).

### 하루의 흐름

**메인 고정일**은 예전처럼 아침 사건 -> 낮 선택 -> 저녁 사건(영업) -> 밤 이고, **일상일**은 아래처럼 짧게 굴러갑니다 (2~4분).

1. **아침**: 일차 카드(호감도/피로 + 오늘의 한 줄 문구) -> (확률로 아침 랜덤 사건)
2. **낮**: 히로인 4명 중 한 명과 시간을 보내거나(다음 순서 이벤트 또는 "평범한 하루"), 조건이 맞는 **깊은 이야기**가 있으면 그것, 또는 낮 행동 4가지 중 하나: **여관 일 집중**(+30G, 평판+1, 피로+12) / **푹 쉬기**(피로-35) / **이웃 마을 장보기**(오늘 재료 -20% 또는 희귀 재료, 피로+6~12) / **여관 손보기**(평판+1, -6G, 피로+8)
3. **저녁**: 영업 (그날의 손님을 시드로 자동 생성: 주차별 3~5명 + 여관 등급/간판 보너스, 히로인이 확률로 방문, 주마다 특별 주문 1~2회)
4. **밤**: 숙박 접수 -> 밤 사건 -> 여관 등급 검사 -> 여관 손보기(업그레이드) -> 호감도가 높은 히로인의 밤 방문(확률)
5. **휴일(일요일)**: 영업/숙박 없음. 낮에 **주간 이벤트**(있으면) 또는 히로인과 산책 / 푹 쉬기. 피로가 크게 풀립니다.

### 주인의 피로 (0~100)

`story/calendar.js` 의 `fatigue` 에서 조절합니다. 영업 +16, 숙박 접수 +5, 낮 행동(`set:{fat:N}`), 잠 -14, 휴일 아침 -50 추가, 푹 쉬기 -35. 60 이상이면 **피곤**(영업 팁 x0.75), 85 이상이면 **과로**(팁 x0.5, 대성공이 25% 확률로 보통으로 미끄러짐). 히로인과 시간을 보내는 낮은 피로를 늘리지 않으므로, 일/영업만 하면 지치고 쉬면 회복되는 흐름이 됩니다.

### 엔딩 (8종, 타이틀의 "엔딩 목록"에 기록)

판정 우선순위는 **배드 > 진 > 개별 > 명가 > 노멀** 입니다. (`story/endings.js` 의 `end_judge`)

- **배드 엔딩**: 평판이 -5 이하로 바닥일 때 (최우선 판정, 여관 폐업 위기).
- **진 엔딩 「은빛 여우관의 가족」**: 29일차 동굴에서 조건부 선택지 **"모두와 함께"**(`flag.true_path`)를 골랐고, 네 명 모두 호감도 하트 4칸 이상, 여관 5성일 때. 네 사람이 모두 여관에 남아 가족이 되는 결말 (연애는 암시만). 선택지는 네 명 호감도 + 여관 5성 조건(`TRUE_COND`)을 만족할 때만 나타납니다.
- **히로인 개별 엔딩 4종**: 한 히로인의 호감도가 **고백 기준(`STORY.loveLine`, 기본 60 = 하트 6칸)** 이상이고 가장 높으면 그 사람의 고백 엔딩. 동점이면 목록 앞쪽(에리온 -> 카엘라 -> 미호 -> 리아) 우선.
- **명가 엔딩 「명가의 간판」**: 아무도 고백 기준에 못 닿았지만 여관이 5성이고 평판 50 이상, 숙박 만족 누적 40 이상 (`MASTER_COND`: 객실 개조 + 손님 요청 맞춤까지 하는 숙련된 경영만 도달).
- **노멀 엔딩**: 위 어느 쪽도 아닐 때 (고르게 어울린 경우).
- 엔딩 도달은 `localStorage` 에 저장됩니다. 획득한 엔딩은 제목과 설명이, 못 얻은 엔딩은 `???` 와 힌트가 보입니다.

### 공략 힌트 (스포일러 약간)

- 호감도 하트는 6칸이 한계선입니다. 한 사람에게 집중하면 2주차부터 밤 방문이 시작됩니다. 모두를 고르게 챙기고 여관을 5성으로 키우면 진 엔딩의 길이 열립니다.
- 히로인의 최애 메뉴를 내면 호감도가 한 번에 +4 (두 번째부터 +2). 낮에 그 사람과 시간을 보내며 흘리는 말을 잘 들으세요. 싫어하는 메뉴는 -2.
- 평판이 걸린 영업: 대성공은 하루 평판 +2까지, 실패는 하루 -3까지만 반영됩니다. 정체불명 요리는 평판에는 영향이 없지만 돈은 못 받습니다.
- 골드가 모자라 유료 선택지가 잠겨도 무료 선택지는 항상 남습니다. 큰 돈은 "마음에 드는 사람을 위한 선물"에 쓰면 효율이 좋습니다.
- 평판이 -5 이하가 되면 배드 엔딩이니, 욕심을 부리는 선택은 몇 번까지만.
- 영업에서는 재료를 골라도 **어떤 요리가 될지 미리 보여 주지 않습니다.** 메뉴판(알게 된 레시피, 재료, 속성)을 보고 기억해서 조합하세요. (설정의 "쉬운 모드"를 켜면 미리보기가 나옵니다)
- 단골 손님마다 **숨은 취향**이 있습니다. 첫 방문 때 흘리는 말과 주문을 맞췄을 때의 반응이 단서이고, 주문을 맞히면서 취향까지 맞추면 팁과 평판이 조금 더 붙습니다. 알아낸 취향은 영업 화면의 **손님 메모**에 기록됩니다.
- **장바구니**: 장보기와 장터(선물 사기)는 품목마다 `[-] 수량 [+]` 로 담고 빼며, 합계와 구매 후 잔액을 보고 **구매 확정**을 눌러야 골드가 빠집니다. "지난번처럼 사기"/"추천 구매"도 담기만 합니다. 담은 채 나가면 한 번 묻고, 장바구니는 저장하지 않습니다. 확정한 뒤에도 같은 날 영업 시작 전(장보기)이나 아직 주지 않은 선물은 `[-]` 로 반품(전액 환불)할 수 있고, 업그레이드/객실 개조는 그 밤 화면을 떠나기 전까지 `취소`(전액 환불, 해금된 레시피도 되돌림)할 수 있습니다.
- 메인 고정일과 일상일의 주마다 1~2번 **특별 주문**이 들어옵니다. 장보기 화면에 예고가 뜨니 재료를 미리 챙기세요. 모든 손님에게 대성공을 내면 보상, 놓쳐도 평판이 조금 깎일 뿐입니다.

## 자유 대화 (PC의 로컬 LLM, 선택 기능)

PC에서 돌아가는 로컬 LLM(Ollama / LM Studio)에게 히로인을 연기시켜서, 폰에서 히로인과 **자유롭게 대화(티키타카)** 할 수 있습니다. 대화 내용은 내 PC 밖으로 나가지 않습니다.
설치와 사용법은 **[pc-server/README.md](pc-server/README.md)** (초보자용, 단계별)를 보세요.

- **PC 서버(`pc-server/start.bat`)로 연 게임에서만** 켜집니다. GitHub Pages(https)에서는 PC의 LLM 주소를 부를 수 없어서, PC가 게임 파일까지 직접 서빙합니다. GitHub Pages 나 오프라인 버전은 기존 그대로 동작하고, 메뉴의 "자유 대화"에 `PC 서버에서 실행할 때만 사용 가능` 이라고만 표시됩니다. (이때 게임은 `/llm/` 으로 요청을 보내지 않습니다.)
- **들어가는 길**: ① 낮에 히로인과 시간을 보내는 이벤트가 끝나면 "조금 더 이야기해 볼까?" 선택지가 나옵니다(7일차 출정 전 포함). ② 메뉴 -> "자유 대화"로 오늘 만난 히로인(저녁부터는 전원)을 골라 시작.
- **규칙**: 히로인 한 명과 하루 6번까지. 호감도는 대화로 히로인당 하루 최대 +3, 전체 합쳐 하루 최대 +4 (깎이는 건 -4까지)라서 대화만으로 호감도를 쌓을 수 없고 엔딩 밸런스는 그대로입니다. 오류로 실패한 턴은 세지 않습니다. 하루 사용량은 세이브에 들어가므로 불러오기로 되돌려도 파밍할 수 없습니다.
- **화면**: 하단 입력창 + 보내기, 답은 기존 대사창에 타이핑 효과, 표정 즉시 교체, 호감도가 오르면 하트 연출, "대화 끝내기", "…생각 중" 표시, 오류 때는 친절한 문구와 "다시 시도" 버튼. 모바일 키보드가 올라와도 입력창이 가려지지 않게 `visualViewport` 에 맞춥니다.
- **프롬프트 / 말투 수정**: `story/llm-persona.js` 한 파일에 모두 있습니다 (공통 지시, 히로인별 성격/말투 예시/호칭, 일차별 비밀 공개 범위, 호감도 구간별 태도, 하루 턴 수/호감도 상한/temperature 등). 최애/싫어하는 메뉴는 `story/tavern.js` 의 정의를 자동으로 읽습니다. 모델은 `{"reply","face","affection"}` JSON 한 줄로 답하도록 지시받고, 형식이 깨져도(코드블록, 잡문, 잘린 JSON, 일반 문장, `<think>` 블록, 영어 응답) 최대한 살려서 표시합니다.
- 검증: `python3 pc-server/test_inn_server.py`(서버), `node tools/test-llm-core.js`(파서/프롬프트/상한), `node tools/test-llm.js`(Playwright 통합, 가짜 LLM `pc-server/fake_llm.py` 사용).

## 저녁 영업 데이터 작성법 (`story/tavern.js`)

코드를 몰라도 글자와 숫자만 바꾸면 영업을 고칠 수 있습니다. 구성은 위에서 아래로 `rules` -> `tags` -> `ingredients` -> `recipes` -> `upgrades` -> `customers` -> `days` 입니다.

### 재료 / 레시피
```js
ingredients: { mead: { name:'꿀술', price:5, icon:'assets/tavern/mead.svg', note:'재료를 눌렀을 때 나오는 한 줄' }, ... }   // 8종
recipes: {
  honey_milk: { name:'꿀술 우유', ing:['milk','mead'], tags:['따뜻함','달콤함'], price:9,
                basic:true,                      // true 면 처음부터 메뉴판에 있음
                hint:'누군가의 어린 시절 추억의 맛.' }   // 아직 모를 때 메뉴판에 보이는 힌트
}
```
- `ing` 은 2~3개, 순서 무관. 같은 조합이 두 레시피에 있으면 안 됩니다(검사기가 확인).
- 처음 메뉴판에 있는 레시피는 `basic`, 나머지는 (1) 대화/이벤트의 `{learn:'id'}`, (2) 손님의 `gain`, (3) 향신료 선반 업그레이드, (4) **재료를 직접 맞춰 보다가 발견** 으로 얻습니다. (총 17개, 처음 5개. 여관 3성에서 허브 꿀차/고기 빵 샌드 2개가 추가로 공개)

### 손님 (`customers`)
```js
baron: { react: { perfect:[{text:'...', face:'smile'}], good:[...], fail:[...], mystery:['{dish}라…?'] } },  // 기본 반응 (여러 개면 무작위)
erion: { heroine:true, fav:'moon_tea', dislike:['meat_stew'],
         react: { ..., fav:[...대사 전부 순서대로...], hate:[...] } }
```
`id` 는 `story/characters.js` 의 캐릭터 id 입니다(그림 6표정 필요). `{dish}` 는 낸 요리 이름으로 바뀝니다. 히로인의 최애/싫어함은 **레시피 id** 입니다. 최애를 내면 주문과 상관없이 대성공으로 처리됩니다.

### 일차별 손님과 주문 (`days`)
```js
day2: { bg:'inn_evening', customers: [
  { who:'tobi',
    say:[{text:'어이쿠, 소문의 은빛 여우관!', face:'smile'}, '문자열이면 그냥 손님이 하는 말'],   // 등장 대사 (명령 객체 {narr:'..'} 도 가능)
    order:{ text:'정신이 번쩍 들면서 입안이 개운한 걸로!', want:['독함','상쾌함'], avoid:['달콤함'] },
    perfect:'이 손님만의 대성공 대사',            // 선택: good / fail / mystery 도 가능 (없으면 customers 의 기본 반응)
    after:[{text:'줄거리 전달용 대사'}],          // 반응 뒤에 이어 붙음
    gain:{ learn:'herb_roast', on:['perfect','good'], lines:[...] },   // 결과가 on 에 들면 레시피 해금 + 대사
    if:'tavern.upg.sign' }                        // 조건을 만족할 때만 등장 (간판 업그레이드 +1명)
] }
```
- `want` 의 태그를 **전부** 가진 요리 = 대성공, **하나라도** = 보통, 없으면 실패. `avoid` 태그가 들어 있으면 대성공 불가.
- 스토리에서는 `{tavern:'day2'}` 한 줄로 시작합니다. 영업 직전/직후 장면은 스토리 씬(`d2_evening`, `d2_ev_cellar` ...)에 씁니다.
- 새 날을 만들 때는 `days` 에 id 를 추가하고 `{tavern:'새id'}` 를 쓰면 됩니다. 영업 결과(`tavern.t.perfect` 등)는 바로 조건식에서 쓸 수 있습니다.

### 단골 숨은 취향 (`customers.<id>.taste`)
히로인이 아닌 단골 6명(바론, 토비, 그레타, 마르타, 핀, 촌장)마다 숨은 취향이 하나씩 있습니다.
```js
baron: { taste: { tag: '든든함', label: '든든한 요리',                       // tag(속성) 또는 ing(재료 id) 중 하나
                  first: [{ text:'첫 방문 때 흘리는 은근한 힌트', face:'normal' }],
                  miss:  [{ text:'주문은 맞췄는데 취향은 못 맞췄을 때 (한 번) 하는 힌트', face:'sad' }],
                  bonus: [{ text:'취향을 맞췄을 때 대사', face:'smile' }] }, react: {...} }
```
- 주문을 **대성공/보통으로 맞히면서** 취향까지 맞으면 **단골 보너스**: 팁 +`rules.tasteTip`, 평판 +`rules.tasteRep` (평판은 하루 상한 안에서만). 최애/싫어함이 있는 히로인에게는 없습니다.
- 알아낸 취향은 영업 화면의 **손님 메모**(재료 고르기/장보기 화면의 버튼)에 공개되고, 모르는 취향은 `???` 와 들은 힌트 대사가 기록됩니다. 히로인은 최애 메뉴(발견하면)/싫어하는 메뉴(겪으면)가 기록되고 모르면 `???` + 레시피 힌트가 보입니다.

| 단골 | 숨은 취향 | 단서 |
|---|---|---|
| 바론 영감 | 든든한 요리 (태그 든든함) | "뱃속에 묵직하게 남는 게 더 좋더구먼" |
| 토비 | 에일이 들어간 요리 | "거품 올라오는 한 잔 앞에서 해야 협상이 풀린다" |
| 그레타 | 고기가 들어간 요리 | "씹는 맛이 없으면 먹은 것 같지가 않아" |
| 마르타 | 빵이 들어간 요리 | "식사에 빵이 없으면 허전하더라고요" |
| 핀 | 달콤한 요리 (태그 달콤함) | "순찰 돌 때 주머니에 사탕이 있으면 힘이 나요" |
| 촌장님 | 우유가 들어간 요리 | "속이 예민해서 부드럽게 넘어가는 게 제일이라네" |

### 특별 주문 (`specials`)
2~7일차(`specials.day2` ~ `day7`)에 하루 한 번, 그날 일반 손님이 끝난 뒤 이어서 나옵니다. 장보기 화면에 `brief` 예고가 뜹니다.
```js
day4: { title: '모험가 파티 3인분', brief: '장보기 화면에 보이는 예고',
        win:  { gold: 22, rep: 2, lines: [...] },        // 모든 손님에게 대성공을 내면 보상
        lose: { rep: -1, lines: [...] },                  // 하나라도 놓치면 평판이 조금 깎일 뿐 (골드 페널티 없음)
        units: [ { who:'greta', say:[...],
                   order:{ text:'...', want:['독함','든든함'], avoid:[...],
                           ing:['meat'], noIng:[...],     // (선택) 꼭 들어가야 하는/들어가면 안 되는 재료
                           note:'주문서에 따로 적히는 조건 한 줄' } }, ... ] }
```
- 6일차 영업은 `day6`(정상)과 `day6free`(무료 배식) 두 가지입니다. `day6free` 는 `day6` 를 복사해 `free:true` 를 붙인 것으로, 요리 값/팁/특별 주문 골드가 0 이고 평판과 호감도만 오릅니다 (`js/tavern-core.js` 의 `serve` 가 `ctx.free` 를 보고 처리).
- `units` 가 1명이면 "조건 두 가지를 한 접시에"(예: 촌장의 축제 요리), 여러 명이면 "연속으로 서로 다른 조건"(예: 모험가 파티 3인분)입니다. 재료 조건(`ing`/`noIng`)을 어기면 태그가 맞아도 대성공이 아니라 보통이 됩니다.
- 특별 주문 손님은 건별 평판이 없고(요리 값/팁은 일반 손님처럼 받음), 보상/벌점의 평판도 **하루 평판 한계(+2/-3) 안에서만** 반영됩니다. 결산에 성공/실패가 표시되고 `tavern.sp.day2`('win'/'lose'), `tavern.spWin`, `tavern.spLose` 로 스토리 조건식에서 쓸 수 있습니다.

| 일차 | 특별 주문 | 조건 | 보상 / 실패 |
|---|---|---|---|
| 2 | 행상인의 시식 주문 (토비, 1접시) | 든든함 + 빵이 들어갈 것 + 술(독함) 안 됨 | +10G 평판 +1 / 평판 -1 |
| 3 | 촌장의 축제 요리 (촌장님, 1접시) | 따뜻함 + 든든함 + 버섯이 들어갈 것 + 술/단맛 안 됨 | +14G 평판 +1 / 평판 -1 |
| 4 | 모험가 파티 3인분 (그레타 -> 토비 -> 핀, 연속 3개) | 독함+든든함 / 상쾌함+독함(단맛 안 됨) / 든든함+고기 들어감(술 안 됨) | +22G 평판 +2 / 평판 -1 |
| 5 | 사절단장의 시식 주문 (이졸데, 1접시) | 따뜻함 + 상쾌함 + 허브가 들어갈 것 + 술 안 됨 | +24G 평판 +2 / 평판 -1 |
| 6 | 폭풍 속 한 솥 (촌장님 -> 마르타, 연속 2개) | 따뜻함+든든함+고기(술 안 됨) / 달콤함+든든함+빵(술 안 됨) | +16G 평판 +2 / 평판 -1 (무료 배식 `day6free` 에서는 골드 없음) |
| 7 | 노인들의 마지막 부탁 (바론 -> 마르타, 연속 2개) | 따뜻함+든든함+버섯 / 달콤함+든든함+꿀술(독함 안 됨) | +14G 평판 +1 / 평판 -1 |

### 규칙 수치 (`rules`) 와 업그레이드 (`upgrades`)
`rules.pay`(결과별 요리 값 비율), `tipRate`, `rep`(손님 1명당 평판), `repDay`(하루 평판 증감 한계), `love`/`favLove`(호감도), 업그레이드 `price`/`desc` 를 바꾸면 밸런스가 달라집니다. 바꾼 뒤 `node tools/check-story.js` 로 엔딩 분포와 골드 수지를 확인하세요. 새 업그레이드 효과를 만들려면 `js/tavern-core.js` 의 `serve()` 에 id 별 처리를 추가해야 합니다(`learn:['레시피id']` 가 있으면 구입 즉시 해금되는 종류는 코드 수정 없이 추가 가능).

### 밸런스 (현재 설정, `node tools/check-story.js --weeks` 시뮬레이션)

- 영업 플레이어는 **"메뉴판을 기억하는 플레이어"** (숙련 97% / 보통 75% / 서툰 40% / 대충 0% 확률로 메뉴판대로 맞춤). 낮 행동 모델은 균등 분배 / 모두 챙기기 / 경영 올인 / 한 명 집중 등이고, 피로가 높으면 쉽니다.
- **여관 등급 기준** 8 / 26 / 48 / 72 (등급 점수 = 평판 + 숙박 만족). 주 끝 평균 등급: 1주 1.5~2.0★ -> 2주 1.9~2.7★ -> 3주 2.6~3.8★ -> 4주 숙련 4.6~4.8★ / 보통 4.0~4.5★ / 서툰 2.9~3.2★ / 대충 2.0~2.1★ (경영 올인은 2주차에 이미 4~5★).
- `STORY.loveLine` 60 (HEART(n)=ceil(60n/6): 1칸 10, 2칸 20, 3칸 30, 4칸 40, 6칸 60). **2단계(콘텐츠 확장) 후 목표/결과** (`node tools/check-story.js` 가 "경영 올인 전략" 줄까지 출력):
  - 한 명 집중: 숙련/보통 영업 약 99% 개별 엔딩 (서툰 영업 약 93%, 대충은 약 30%).
  - 모두 챙기기(+ 동굴 "모두와 함께"): 숙련 영업은 진 엔딩 80% (2단계 전 75%), 보통 영업은 41% (전 42%), 서툰/대충은 0%.
  - 경영 올인(히로인은 거의 안 만남): **명가 엔딩이 숙련 영업만의 길** — 숙련 95% / 보통 0% / 서툰 0% / 대충 0% (2단계 전: 숙련 97% / 보통 100% / 서툰 33% / 대충 0%, 즉 보통만 해도 거의 100%). 이를 위해 `MASTER_COND` 에 **숙박 만족 누적 40 이상**을 추가했습니다 (숙련 49~56, 보통 30~36, 서툰 12~18). 객실 개조 4개를 모두 하고 손님 요청을 계속 맞춰야 도달합니다.
  - 평판 최저 선택: 서툰/대충 영업은 배드, 숙련/보통 영업은 꾸준한 영업 덕에 노멀 (2단계 전과 같음).
  - 무작위 6000회: 노멀 76% / 배드 10% / 명가 4% (전 14%) / 개별 엔딩 각 2~3%.
  - 한 회차에 읽는 대사는 중앙값 약 540줄(최소 약 465, 최대 약 635줄) — 이벤트가 늘어도 한 회차에서 한 명이 볼 수 있는 이벤트 수는 비슷하고, 대신 다음 회차에 보는 이벤트가 많이 달라집니다.
- 재료 값은 주마다 +0/8/16/24/30%. 업그레이드는 1단계 4개(술통 40 / 향신료 선반 60 / 난로 35 / 새 간판 55) + 저장고 100(재료 -12%) + 2단계 3개(명품 술통 160 / 큰 화덕 130 / 큰 간판 180, 1단계 필요). 일상일 영업은 주차별 일반 손님 3/4/4/5/5명(+여관 3성 이상 +1, 간판 +1/+2), 히로인 방문 32%/일, 특별 주문 1/2/2/2회(주).
- 일상일 영업 하루 순이익(매출+팁-재료비, 균등 분배 기준)은 숙련 약 +32G, 보통 약 +19G, 서툰 약 -5G, 대충 약 -14G (숙박 수입/업그레이드/선물 제외).

## 플레이 방법

- **화면 탭**: 글자가 타이핑되는 중이면 즉시 전부 표시, 다시 탭하면 다음 대사 (데스크톱은 스페이스/엔터도 가능)
- **선택지**: 큰 버튼을 눌러 선택. 히로인 선택지는 얼굴과 현재 호감도 하트가 표시되고, 유료 선택지는 `-8G` 처럼 비용이 보입니다.
- **상단 HUD**: 현재 일차/시간대, 골드, 평판. 호감도가 오르면 하트가 떠오르고 알림이 뜹니다.
- **오토 / 스킵 (대사창 오른쪽 위의 작은 버튼)**
  - **스킵**: 이미 읽은 대사를 빠르게 넘깁니다. 처음 보는 대사, 선택지, 영업, 엔딩, 일차 카드, 결과 화면, 자유 대화에서는 자동으로 멈춥니다. 읽은 대사 기록은 회차와 상관없이 브라우저에 저장됩니다. (설정의 "안 읽은 대사도 스킵"을 켜면 처음 보는 대사도 넘깁니다. 영업 중 손님 대사는 스킵하지 않습니다)
  - **오토**: 글자가 다 나온 뒤 (기본 지연 + 글자 수에 비례한 시간) 지나면 자동으로 다음 줄로 넘어갑니다. 선택지 등에서 멈춥니다.
  - 둘 다 **화면을 탭하면 꺼집니다.**
- **설정 (메뉴 -> 설정, 타이틀의 설정 버튼)**: 글자 속도, 오토 속도, BGM 볼륨, 효과음 볼륨, 전체 음소거, 안 읽은 대사도 스킵, 쉬운 모드(영업 미리보기), **영업 빠른 모드**(손님 등장 대사 한 줄 + 반응 뒤 덧붙는 대사 생략 + 도장 연출 단축), **살 게 없으면 손보기 건너뛰기**(밤의 여관 손보기에서 살 수 있는 게 없으면 화면 생략). 바꾸는 즉시 `localStorage` 에 저장됩니다.
- **메뉴(오른쪽 위)**: 저장(3슬롯) / 불러오기 / 백로그(지난 대사) / 설정 / 처음부터 / 타이틀로
- **자동 저장**: 대사가 바뀔 때마다 저장되며, 타이틀의 "이어하기"로 이어서 합니다. 저녁 영업 중에는 영업 시작 시점으로 저장됩니다.
- 저장은 브라우저 `localStorage` 를 사용합니다 (막힌 환경에서도 게임 자체는 동작). 세이브 키에는 버전(`inn_vn_v5_`)이 붙어 있어 옛 버전(v4 이하) 세이브는 읽지 않고 무시합니다 (7일 구성으로 씬 id 가 바뀌었기 때문. 엔딩/CG/레시피/손님 메모/튜토리얼/설정 기록은 처음 한 번 v4 에서 v5 로 옮겨 오고, 읽은 대사 기록은 옮기지 않습니다)(타이틀은 정상, 이어하기만 꺼짐). 엔딩/CG/레시피/메모/튜토리얼 같은 영구 기록은 첫 실행에서 v3 -> v4 로 한 번만 옮겨 집니다. (숙박/등급/선물 변수가 추가되어 세이브가 호환되지 않음)

## 실행 / 배포

```bash
cd inn-vn
python3 -m http.server 8000     # http://localhost:8000 접속
```

- `index.html` 을 `file://` 로 직접 열어도 게임은 동작합니다 (스토리를 fetch 가 아닌 `<script>` 로 읽음). 단 PWA/서비스 워커는 http(s) 에서만 동작합니다.
- **GitHub Pages**: 저장소 루트에 이 폴더 내용을 올리고 Settings > Pages 에서 main 브랜치 / root 를 선택하면 끝. 모든 경로가 상대 경로입니다.
- **PWA**: `manifest.webmanifest` + `sw.js` (오프라인 캐시) + 아이콘 포함. 안드로이드 크롬에서 "홈 화면에 추가"가 가능합니다.
  파일을 고쳐 다시 배포할 때는 `sw.js` 맨 위 `VERSION` 을 올리면 폰에 남은 옛 캐시가 정리됩니다. 새 이미지/스토리 파일을 추가했다면 `sw.js` 의 `ASSETS` 목록에도 넣으세요(오프라인 캐시용).
- **APK**: 루트 `index.html` 하나로 동작하므로 Capacitor 등의 `webDir` 로 이 폴더를 그대로 지정하면 됩니다.

## 스크립트 작성법

`story/dayN.js` 는 **씬 id -> 명령 배열** 형태입니다. 명령은 위에서 아래로 한 줄씩 실행되고,
`say` / `narr` / `choice` / `day` / `ending` 에서 멈춰서 플레이어의 입력을 기다립니다.
**모든 씬의 마지막 명령은 `goto`, `choice`, `summary`, `end`, `ending` 중 하나**여야 합니다.

```js
Object.assign(STORY.scenes, {
  my_scene: [
    { bg: 'inn_day' },
    { show: 'kaela', face: 'smile', pos: 'left' },
    { say: 'kaela', text: '안녕, 주인장!' },
    { narr: '카엘라가 크게 웃었다.' },
    { choice: [
      { text: '반갑습니다!', set: { 'aff.kaela': 1 }, goto: 'scene_a' },
      { text: '꿀케이크를 건넨다', cost: 8, set: { 'aff.kaela': 2 }, goto: 'scene_b' }
    ] }
  ],
  scene_a: [ /* ... */ { goto: 'my_next' } ]
});
```

### 명령어 레퍼런스

| 명령 | 설명 | 예시 |
|---|---|---|
| `{bg: id}` | 배경 변경 (`backgrounds.js` 의 id) | `{bg:'cave_inside'}` |
| `{show: id, face, pos}` | 캐릭터 등장/표정·위치 변경. `pos` 는 `left`/`center`/`right`. 이미 화면에 있는 캐릭터는 `pos` 를 생략하면 제자리를 유지하고, 새로 등장하면 가운데. `face` 생략 시 현재/첫 표정 | `{show:'miho', face:'shy', pos:'right'}` |
| `{hide: id}` | 캐릭터 퇴장. `'all'` 이면 전원. (화면은 3자리뿐이라 4명이 모일 땐 한 명을 `hide`) | `{hide:'all'}` |
| `{say: id, text, face?, as?}` | 대사. `face` 를 주면 그 줄부터 표정 교체, `as` 는 표시 이름 덮어쓰기(예: `'???'`). 화면에 없는 캐릭터가 `face` 와 함께 말하면 가운데 자동 등장(그래서 화면 밖 캐릭터의 대사에는 `face` 를 빼는 편이 안전) | `{say:'erion', face:'angry', text:'...'}` |
| `{narr: text}` | 이름표 없는 나레이션 | `{narr:'밤이 깊었다.'}` |
| `{choice: [...]}` | 선택지. 항목 아래 표 참고. `goto` 가 없으면 선택 후 다음 명령으로 계속 | 위 예시 |
| `{if: '조건', goto: 씬, else?: 씬}` | 조건이 참이면 `goto`, 거짓이면 `else`(없으면 그냥 다음 명령) | `{if:'aff.erion>=aff.kaela', goto:'x'}` |
| `{goto: 씬}` | 다른 씬으로 이동 | `{goto:'d2_open'}` |
| `{set: {...}}` | 변수 변경. **숫자는 더하기**, `true/false`/문자열은 대입 | `{set:{gold:-5, 'flag.met':true}}` |
| `{put: {...}}` | 숫자를 **그 값으로 덮어쓰기** | `{put:{gold:100}}` |
| `{day: 'next', time?, tip?}` | **일차 전환 화면**: 다음 날로 넘기며(`'next'`, 첫날만 숫자 `1`) 주차/요일/오늘의 난수/피로 회복을 갱신하고, "N일차 · 주차 요일" 카드와 호감도/피로 현황을 보여 줍니다. 챕터 첫 날이면 챕터 타이틀 카드가 먼저 나오고 "주차 시작" 자동 저장. `tip` 은 카드 아래 안내(`{flav.morning}` 같은 변수 가능) | `{day:'next', time:'아침', tip:'{flav.morning}'}` |

### 변수와 조건식

- 기본 변수: `gold`(골드), `rep`(평판), `day`(일차), `aff.<캐릭터id>`(호감도), `ev.<캐릭터id>`(그 히로인의 낮 이벤트를 본 횟수), `flag.<이름>`(자유롭게 만드는 true/false 표시)
- 영업 결과 변수(스토리 조건식에서 사용 가능): `tavern.perfect` / `tavern.good` / `tavern.fail` / `tavern.mystery`(지금까지 낸 요리 결과 누계), `tavern.t.perfect` ...(가장 최근 영업), `tavern.fav.<히로인id>`(최애 메뉴를 낸 횟수), `tavern.known.<레시피id>`(아는 레시피), `tavern.upg.<업그레이드id>`(구입한 업그레이드), `tavern.stock.<재료id>`(재고), `tavern.sales` / `tavern.tips`(누적 매출/팁). 예: `{if:'tavern.perfect>=6', goto:'x'}`
- 2단계 변수: `ser.<이름>`(연작 랜덤 사건의 본 부 수, 0~3. 사건에서 쓸 수 있는 유일한 진행 변수), `evdone.<씬/이벤트 id>`(한 번 본 휴일/토요일/평범한 하루 장면 표시), `wk`(주 시작 기준값 {day, gold, rep, aff, rank} — 주간 정산 카드 계산용, 챕터 시작일마다 갱신), `cal.week`/`cal.dow`/`cal.hol`(오늘의 주차/요일(0=월)/휴일, 밤 사건이나 낮 행동 조건식에 사용: `cal.dow==5 && cal.week==3`).
- 시작 값은 `story/common.js` 의 `STORY.init` 에서 정합니다. 고백 기준 호감도는 같은 파일의 `STORY.loveLine`(기본 25).
- 조건식: `gold>=30`, `aff.kaela==2`, `flag.met_kael`, `!flag.erion_left`, `rep>0 && aff.erion>=1`, `a || b` (`&&` 가 `||` 보다 먼저 계산, 괄호는 없음). **오른쪽에 변수 이름을 써서 변수끼리 비교할 수도 있습니다**: `aff.erion>=aff.kaela`
- 도우미 함수(스크립트는 JS 라서 쓸 수 있음): `WIN('erion', 8)` = "에리온의 호감도가 8 이상이고 다른 히로인보다 높거나 같다" 를 조건식 문자열로 만들어 줍니다. 밤 방문과 엔딩 판정에 사용.
- 대사 안에 `{gold}` 처럼 쓰면 현재 값으로 바뀝니다. (예: `'금고에는 {gold} 골드가 있다.'`)
- 호감도/골드/평판이 바뀌면 화면에 자동으로 알림이 뜹니다.

### 달력과 일정 (`story/calendar.js`)

`CALENDAR.main` 에 일차를 추가하면 그날이 메인 고정일이 됩니다: `{ scene:'아침씬', evening:'저녁씬(생략하면 일상일 저녁)', title:'달력 이름', mark:'★', show:'이 일차부터 미리 달력에 보임(생략하면 지나간 뒤)' }`. 아침 씬은 `{day:'next', …}` 로 시작해야 하고, 낮에는 `{goto:'pick'}` (또는 직접 선택지)로 넘어가며, 저녁이 끝나면 `{goto:'night_close'}` 로 밤 처리 -> 다음 날로 이어집니다. 챕터/주차 수/요일/물가/피로 수치도 같은 파일입니다. `stages` 는 자유 대화(LLM)가 "이야기가 어디까지 진행됐나"를 판단하는 메인 일차 목록입니다 (`story/llm-persona.js` 의 `days`/`reveal` 키 1~7 에 해당).

### 히로인 이벤트 추가법 (`story/heroine-events.js`)

1. `HEROINE_EVENTS.<히로인id>` 배열에 한 줄을 추가: `{ id:'erion_6', scene:'erion_6', text:'선택지에 보이는 한 줄', minWeek:3, minAff: HEART(3) }`.
   - 조건(모두 만족해야 열림): `minWeek`/`maxWeek`(주차), `minDay`/`maxDay`(일차), `minAff`(그 히로인 호감도 값, `HEART(n)` = 하트 n칸), `if`(조건식, `&&` 만).
   - `kind` 를 생략하면 **순서 이벤트**: "그 히로인을 N번째로 골랐을 때" 배열 순서대로 열립니다. 조건이 아직 안 맞으면 그 히로인은 "평범한 하루"로 대체됩니다 (`story/plain-days.js`). 순서 이벤트가 모두 소진되면 평범한 하루만 나옵니다.
   - `kind:'extra'` 는 순서와 무관한 **조건 이벤트**(깊은 이야기 등). 조건이 맞으면 별도 선택지로 나오고 한 번 보면 사라집니다 (`evdone.<id>`).
2. 같은 이름의 장면을 만듭니다. 순서 이벤트 장면은 `{set:{'ev.<히로인id>':1}}` 로 시작하고 모두 `{goto:'after_pick'}` 로 끝납니다. (CG 를 쓰면 `{cg:'hide'}` 는 `after_pick` 이 걷어 줍니다)
3. 새 파일에 만들었다면 `index.html` 의 스크립트 목록과 `sw.js` 의 `ASSETS` 에 추가하고 `node tools/check-story.js` 를 돌립니다 (없는 씬/도달 불가 씬/조건식 오류를 알려 줍니다).
4. 평범한 하루를 늘리려면 `PLAIN_DAYS.<id>` 에 `{scene, text, maxWeek?/minWeek?/minAff?/if?}` 를 추가하고 장면에 `{set:{'aff.<id>':1,'pl.<id>':1,'evdone.<scene id>':true}}` 를 넣습니다. 지금은 히로인당 10개(기본 6 + 1주차~2주차 한정 1 + 3주차 이후 1 + 하트 2칸 이상 1 + 4주차 이후 1)이고, 조건이 맞는 것 중 아직 안 본 것부터 나오며 다 보면 같은 장면을 돌려 씁니다.

## BGM 넣는 법

효과음은 코드가 직접 합성하지만(`js/sfx.js`), **BGM 은 실제 음악 파일이 필요합니다.** 지금은 파일이 하나도 없어서 `story/audio.js` 의 모든 트랙이 `file: null` 이고, 이 경우 게임은 BGM 을 재생하지도, 파일을 요청하지도 않습니다 (콘솔 오류/404 없음).

1. 음악 파일을 `assets/bgm/` 폴더에 넣습니다. (예: `assets/bgm/inn_day.ogg`)
2. `story/audio.js` 에서 그 트랙의 `file` 에 경로를 적습니다.
   ```js
   inn_day: { file: 'assets/bgm/inn_day.ogg', gain: 0.8 },   // gain(0~1): 이 곡만 소리를 줄이고 싶을 때. loop:false 면 반복 안 함
   ```
3. 새 파일을 `sw.js` 의 `ASSETS` 목록에 넣고 `VERSION` 을 올리면 오프라인(PWA)에서도 들립니다. (용량이 크면 목록에 넣지 않아도 되지만, 그러면 오프라인에서는 BGM 이 안 나옵니다)
4. `node tools/check-story.js` 가 경로/파일 존재/트랙 id 를 검사합니다.

사용되는 트랙 id 와 쓰임: `title`(타이틀), `inn_day`(여관의 낮/아침), `inn_night`(밤), `tavern`(저녁 영업), `festival`(3일차 달맞이 장터), `tension`(지진/습격/결전 직전), `cave`(동굴 안), `romance`(히로인과 단둘이 있는 밤/소원 등불), `ending_good`(개별·노멀 엔딩), `ending_bad`(배드 엔딩). 어느 장면에서 틀지는 `story/day*.js`, `story/endings.js` 의 `{bgm:'...'}` 명령입니다.

- **권장 형식**: 모바일 호환을 위해 **mp3**(또는 ogg). 반복되는 곡이라 앞뒤가 이어지는(루프 가능한) 곡이 좋습니다.
- **권장 용량**: 곡당 1~2MB(2~3분, 96~128kbps 정도), 전체 10곡 합쳐 15MB 이내. GitHub Pages 와 모바일 데이터를 생각해 너무 크게 만들지 마세요.
- **라이선스 주의**: AI 로 만든 음악(Suno, Udio 등)이나 CC0/무료 음원을 쓸 때는 **상업적 이용, 게임/앱 배포, 재배포 가능 여부와 출처 표기 조건을 반드시 확인**하세요. 서비스 약관이 바뀌거나 무료 플랜은 상업 이용이 안 되는 경우가 있습니다. 출처 표기가 필요한 음원이면 타이틀이나 README 에 크레딧을 남기세요. 라이선스가 불분명한 음원은 넣지 않는 것이 안전합니다.
- 브라우저/모바일은 **첫 터치 전에는 소리를 낼 수 없어서** 타이틀 음악은 첫 탭 뒤에 시작합니다. 탭이 백그라운드로 가면 BGM 이 멈췄다가 돌아오면 이어집니다.

## 첫 영업 튜토리얼

1일차 첫 손님에서 한 번만(회차와 무관) 리아가 6단계로 안내합니다: 주문 읽기 -> 메뉴판 열기 -> 재료 2~3개 고르기 -> 내기 -> 결과 보기 -> 손님 메모. 탭으로 넘기고 "건너뛰기" 가 있습니다. 설정의 "튜토리얼 다시 보기" 는 영업 중이면 즉시, 타이틀이면 다음 새 게임 첫 손님에서 다시 보여 줍니다.

## 이미지 교체 방법

히로인 4명은 ComfyUI 로 만든 일러스트(투명 WebP)이고, 손님(baron 등)은 `tools/gen-chars.js` 가 만든 임시 SVG 입니다. 히로인 그림을 바꾸려면:

1. 캐릭터: 원본 PNG 를 `<id>_<표정>.png` 이름(예 `lia_shy.png`, 표정 6종 × 4명)으로 한 폴더에 모은 뒤 변환합니다. 같은 캐릭터의 표정은 모두 같은 스케일로 처리되어 표정을 바꿔도 위치가 튀지 않습니다.
   ```
   pip install "rembg[cpu]" pillow numpy scipy
   python3 tools/process-sprites.py <원본폴더> [--h 1000] [--q 85]
   ```
   결과로 `assets/char/<id>/<표정>.webp` 와 `face.webp`(얼굴 썸네일)가 만들어집니다. 얼굴 위치는 스크립트 위쪽 `FACE` 표(원본 832x1216 기준 중심 좌표/크기)에서 조정합니다. 첫 실행 때 모델(isnet-anime, 약 176MB)을 내려받으니 네트워크가 필요합니다.
   - 새 히로인을 추가하려면 `story/characters.js` 에서 `faces: heroine('id'), icon: heroineIcon('id')` 를 쓰고 `FACE` 표에도 추가합니다. 손님을 PNG/WebP 로 바꾸려면 `faces(id, 'webp')` 를 쓰면 됩니다(얼굴 아이콘은 `icon` 이 없으면 CSS 로 잘라 씁니다).
   - 히로인은 `normal, smile, angry, shy, surprised` 5종이 필수입니다(검사기가 확인).
2. 배경: `assets/bg/` 에 이미지를 넣고 `story/backgrounds.js` 의 경로를 수정합니다. 권장 비율 9:16(예 1080x1920). 화면 비율이 달라도 `cover` 로 꽉 차게 표시됩니다.
3. 바꾼 파일 경로가 `sw.js` 의 `ASSETS` 목록과 다르면 목록도 고치고 `VERSION` 을 올립니다. (`node tools/check-story.js` 가 불일치를 경고)

SVG 를 계속 쓰면서 그림을 다듬고 싶다면 `node tools/gen-chars.js` 로 전체 표정을 다시 생성할 수 있습니다.
